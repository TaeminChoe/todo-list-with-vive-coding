# scenario-04-edit-todo.md

## User Scenario – Edit Todo

---

## 1. Scenario Overview

- **Scenario ID**: SC-04
- **Title**: 사용자는 할 일 내용을 수정한다
- **Primary Actor**: 사용자
- **Goal**: 사용자는 기존 할 일의 내용을 변경할 수 있다

---

## 2. Preconditions

- TODO 목록 화면이 사용자에게 표시되어 있다
- 목록에 수정할 할 일이 1개 이상 존재한다

---

## 3. Main Flow (Happy Path)

1. 사용자는 수정할 할 일을 목록에서 찾는다.
2. 사용자는 해당 할 일에 대한 수정 동작을 수행한다.
3. 시스템은 수정 가능한 상태(수정 입력 가능 상태)를 사용자에게 제공한다.
4. 사용자는 새로운 내용을 입력한다.
5. 사용자는 수정 내용을 반영하기 위한 동작을 수행한다.
6. 시스템은 수정된 내용이 목록에 표시됨을 사용자에게 보여준다.
7. 사용자는 변경된 내용을 확인한다.

---

## 4. Alternative / Exception Flows

### A1. 수정할 할 일이 없는 경우

- 조건: 목록에 할 일이 존재하지 않는다.
- 흐름:
  1. 사용자는 목록이 비어 있음을 인지한다.
  2. 시스템은 수정할 대상이 없음을 사용자에게 인지시킨다.

### A2. 사용자가 수정을 취소하는 경우

- 조건: 사용자가 수정 가능한 상태에서 수정을 완료하지 않는다.
- 흐름:
  1. 사용자는 수정 취소 동작을 수행한다.
  2. 시스템은 기존 내용이 유지됨을 사용자에게 보여준다.

### E1. 입력이 유효하지 않은 경우

- 조건: 사용자가 유효하지 않은 내용을 입력한다.
- 결과: 시스템은 수정이 반영되지 않았음을 사용자에게 인지시킨다.

### E2. 수정 대상이 더 이상 존재하지 않는 경우

- 조건: 사용자가 수정 반영 동작을 수행하려는 시점에 해당 할 일이 존재하지 않는다.
- 결과: 시스템은 수정이 수행되지 않았음을 사용자에게 인지시킨다.

---

## 5. Postconditions

- 정상적인 경우:
  - 선택한 할 일의 내용이 변경되어 있다.
- 취소한 경우:
  - 선택한 할 일의 내용은 변경되지 않은 상태다.
- 실패한 경우:
  - 목록은 변경되지 않은 상태다.

---

## 6. Notes

- 수정 UI 형태(인라인/모달 등)는 본 시나리오에서 다루지 않는다.
- 입력 검증의 구체 기준은 Acceptance Criteria에서 정의한다.
