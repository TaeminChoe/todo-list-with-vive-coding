# domains-rule.md

## Domain Documentation Rules

---

## 1. 이 문서의 목적

이 문서는 `/docs/domains/` 디렉토리에 위치하는 **Domain 문서**에 대한
작성 규칙과 역할을 정의한다.

- Domain 문서는 **애플리케이션의 데이터 모델과 상태**를 정의한다.
- Domain 문서는 Scenario와 Step에서 참조하는 **기준이 되는 데이터 정의 문서**다.
- 본 문서는 상위 규칙 문서(`00-overview.md`, `01-rules.md` 등)를 위반하지 않으며,
  Domain 레벨에서 필요한 **데이터 정의 규칙을 보완**한다.

---

## 2. Domain 문서의 역할

Domain 문서는 다음을 명확히 정의한다.

- **데이터 구조**: 필드명, 타입, 기본값, 제약조건
- **상태 정의**: 유효한 상태 값과 상태 전이
- **비즈니스 규칙**: 데이터 검증 규칙, 제한사항

Domain 문서는 "사용자 경험"을 다루지 않는다.
(사용자 경험은 Scenario에서만 정의된다.)

---

## 3. 디렉토리 구조

```
/docs/domains
 ├─ domains-rule.md       ← Domain 문서 규칙 (본 문서)
 ├─ template.md           ← Domain 문서 템플릿
 ├─ todo.md               ← TODO 도메인 정의
 └─ ...
```

- Domain 문서는 `/docs/domains/` 하위에만 위치한다.
- 도메인별로 1개의 Domain 문서를 생성한다.

---

## 4. Domain 문서 작성 규칙

### 4.1 데이터 구조 정의

- 모든 필드를 명시적으로 정의한다.
- 필드 정의에는 다음을 포함한다:
  - 필드명 (스네이크케이스)
  - 타입 (TypeScript 타입 표기법 사용)
  - 기본값 (있는 경우)
  - 설명 및 제약조건

예시:
```markdown
- **id** (string, UUID): 고유 식별자. 시스템에서 자동 생성.
- **content** (string): 할 일 내용. 1자 이상 255자 이하.
- **status** ("COMPLETE" | "NOT_COMPLETE"): 완료 여부. 기본값 "NOT_COMPLETE".
```

### 4.2 상태 정의

- 상태는 **유한한 집합**으로 명시한다.
- 문자열 자유 입력을 상태로 사용하지 않는다.
- 가능한 모든 상태 값을 나열한다.

### 4.3 단정형 작성

- 규칙 문서와 마찬가지로 단정형 문장만 사용한다.
- 모호한 표현("적절히", "필요에 따라")은 금지한다.

---

## 5. Domain 문서 참조 규칙

### 5.1 AI 참조 규칙

- AI는 Domain 문서를 **참조만 할 수 있다.**
- AI는 Domain 문서를 수정하지 않는다.

### 5.2 Step 문서에서의 참조

- Step 문서는 필요시 Domain 문서를 References에 명시할 수 있다.
- Domain 문서가 명시되면, Step의 구현은 해당 Domain 정의를 따라야 한다.

---

## 6. Domain 문서 수정 규칙

- Domain 문서는 **사용자만 수정할 수 있다.**
- Domain 문서 수정 시, 영향을 받는 Step 문서를 검토해야 한다.
- 기존 필드 삭제나 타입 변경은 주의가 필요하다.

---

## 7. Domain 문서 템플릿 준수 규칙

- `/docs/domains/` 하위에 작성되는 모든 Domain 문서는
  `template.md`에 정의된 형식과 구조를 따른다.
- 템플릿을 따르지 않은 Domain 문서는 유효한 도메인 정의로 간주하지 않는다.

---

## 8. 이 문서의 위상

이 문서는 `/docs/domains/` 하위에서
Domain 문서에 대한 **최상위 규칙 문서**다.

본 문서의 규칙을 따르지 않는 Domain 문서는
유효한 도메인 정의로 간주되지 않는다.
