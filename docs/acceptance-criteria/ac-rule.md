# ac-rule.md

## Acceptance Criteria Rules (Project-level)

---

## 1. 이 문서의 목적

이 문서는 `/docs/acceptance-criteria/` 디렉토리 하위에서 사용되는
**Acceptance Criteria(AC) 문서 작성 규칙**을 정의한다.

- 본 문서는 상위 글로벌 규칙 문서인 `03-acceptance-criteria.md`를 **참조하고 확장**한다.
- 상위 문서가 모든 프로젝트에 공통으로 적용되는 규칙이라면,
  본 문서는 **이번 프로젝트에 특화된 AC 작성 기준**을 정의한다.
- 상위 규칙과 충돌하는 내용은 작성할 수 없다.

---

## 2. Acceptance Criteria의 역할 (재정의)

Acceptance Criteria는 다음 질문에 답하기 위한 문서다.

> “이 기능(또는 흐름)이 **성공했다고 판단할 수 있는 조건은 무엇인가?**”

- AC는 요구사항 목록이 아니다.
- AC는 구현 방법을 설명하지 않는다.
- AC는 테스트 코드와 **1:1 또는 N:1로 매핑 가능한 판정 기준**이다.

---

## 3. AC와 다른 문서 간의 관계

- Scenario → “무슨 일이 일어나는가”
- Acceptance Criteria → “성공/실패를 어떻게 판단하는가”
- Step → “AC를 충족시키기 위해 무엇을 실행하는가”

AC 문서는:

- 하나 이상의 Scenario에서 도출될 수 있다.
- 여러 Step에서 분할 구현될 수 있다.

---

## 4. AC 작성 단위 규칙

- AC 문서는 **기능 또는 사용자 흐름 단위**로 작성한다.
- 하나의 AC 문서는 여러 개의 개별 AC 항목을 포함할 수 있다.
- AC 항목은 반드시 **고유한 AC ID**를 가진다.

예:

- 문서 ID: `ac-01-create-todo.md`
- 항목 ID:
  - AC-01-01
  - AC-01-02

---

## 5. AC 서술 규칙 (중요)

각 AC 항목은 다음 조건을 만족해야 한다.

- 관찰 가능한 결과로 서술한다.
- UI/UX 세부 구현(레이아웃, 색상, 클래스명 등)을 언급하지 않는다.
- 내부 로직, 상태 관리, API 호출을 언급하지 않는다.
- 테스트 가능해야 한다.

권장 문장 형태:

- “~하면, ~가 된다”
- “~한 경우, ~는 발생하지 않는다”

---

## 6. AC 수정 규칙

- AC 문서는 사용자만 수정할 수 있다.
- AI는 AC 문서를 직접 수정하지 않는다.
- AC 문서가 수정되면:
  - 이를 참조하는 Step 문서는 재검토 대상이 된다.
  - 자동으로 수정되지는 않는다.

---

## X. AC 문서 템플릿 준수 규칙

- `/docs/acceptance-criteria/` 하위에 작성되는 모든 AC 문서는
  `template.md`에 정의된 형식과 구조를 반드시 따른다.
- 템플릿을 따르지 않은 AC 문서는 유효한 판정 기준으로 간주하지 않는다.
- 템플릿과 AC 문서 간 내용 충돌이 발생하는 경우,
  다음 우선순위를 따른다.

우선순위:

1. 03-acceptance-criteria.md (글로벌 규칙)
2. ac-rule.md (프로젝트 규칙)
3. template.md (형식 정의)
4. 개별 AC 문서

---

## 7. 이 문서의 위상

이 문서는 `/docs/acceptance-criteria/` 하위에서
Acceptance Criteria 문서에 대한 **프로젝트 레벨 규칙 문서**다.

본 문서의 규칙은 상위 `03-acceptance-criteria.md`를 보완하며,
이를 위반할 수 없다.
